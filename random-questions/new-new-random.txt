Sharing a few questions that were discussed 👇

🔹 Project Discussion

• Explain your current project and your responsibilities.
• How is your application structured from frontend to backend?
• How do you handle communication between different modules?
• Tell me about a production issue you faced and how you resolved it.

🔹 React.js — Practical Scenarios

👉 You have a React page where changing one filter causes the entire page to re-render. How would you identify what is actually re-rendering and optimize it?

👉 Your application has a complex form with multiple sections. How would you manage the form state and validation without making the component difficult to maintain?

👉 A user clicks the Submit button multiple times and creates duplicate API requests. How would you prevent this?

👉 You need to display continuously updating data on a dashboard. Would you use polling, WebSockets, or another approach? Why?

👉 A component has become 1,000+ lines long. How would you refactor it without breaking existing functionality?

🔹 JavaScript & APIs

• You have 5 APIs that need to execute before rendering a page. How would you handle them efficiently?

• One API fails while the other four succeed. How would you design the error-handling strategy?

• An API response contains thousands of records. Would you process everything on the frontend? What alternatives would you consider?

🔹 Performance

👉 The Lighthouse performance score of a React application is poor.

What would you check first, and what steps would you take to improve it?

👉 A JavaScript function is causing noticeable UI lag.

How would you identify the issue and optimize it?

Memory management in React applications.

Most engineers don't think about it — until users start complaining that the app gets slower after 30 minutes of use.

Or until a browser tab crashes.
Or until a laptop fan won't stop spinning.

Memory leaks in React are rarely caused by one big mistake.

They come from small, overlooked details:
— a forgotten cleanup in useEffect;
— an uncleared interval;
— an unremoved event listener;
— a WebSocket that never closes;
— a fetch request that resolves after unmount.

I've spent a lot of time debugging and preventing these issues in production apps.
